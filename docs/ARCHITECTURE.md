# Quill architecture

Electron owns disk access, recovery files, settings, file watching, and subprocesses. A sandboxed renderer communicates through a narrow preload API. No Node APIs, arbitrary shell execution, or remote content run in the renderer. Projects are ordinary folders and source is UTF-8 text. Build programs and argument arrays are separate; compilation disables TeX shell escape. Disk writes compare content hashes, then atomically rename a temporary sibling file.

CodeMirror 6 owns document state, history, multiple selections, search, highlighting, and mapped snippet ranges. Editing features are extensions, not DOM input mutations. Pure core modules expose context, snippets, navigation, configuration, and indexing APIs independently of the UI. The command registry connects palette, menus, and configurable contextual/chord keybindings. Providers can later register more commands and completions without a general-purpose plugin runtime.

## Subsystem contracts

- `ContextIndex.update(text, changedFrom)` invalidates line checkpoints from the edit. `at(offset)` returns mode, comment, environment stack, and enclosing command argument. Checkpoints are populated lazily; typing near the end of a stable file only scans the changed suffix.
- Snippet data: id, name, trigger, replacement (`${1:default}`, `$2`, `$0`), context, group, enabled, auto, priority, retainTrigger, recursive, and literal/regex kind. `matchSnippet` returns a text edit and ordered placeholder ranges. Regex rules have bounded input and reject unsafe expressions. Recursion is opt-in and expansion depth is capped.
- Navigation: `navigate(text, position, action)` returns a logical position; pairs account for escaped braces and comments. Commands expose this engine without knowing the UI.
- `indexDocument(path,text)` returns sections, labels, command definitions, environments, and bibliography entries. A worker indexes only changed files, off the typing path.
- Configuration: versioned JSON defaults plus global and project overrides. GUI editors use the same validation entry point as imports. Invalid data cannot replace the active configuration.
- PDF preview: `PdfPreview.load(readBytes, documentKey)` loads a replacement with generation checks, preserves the live reading anchor, renders visible pages before committing, and keeps the prior document if loading/rendering fails. `clear()` saves per-document position and invalidates pending work when switching projects. Zoom/resize retain page-relative offsets; hidden panes defer position restoration until visible. PDF.js and its worker/fonts/CMaps/WASM are bundled locally, with the main library loaded lazily.
- Host: folder listing, read, conditional write, create/rename/trash, configuration, recovery, build/cancel, PDF bytes, and change events. Browser mode uses an explicitly labeled local demo adapter and import/download; native capabilities require Electron.

## Milestones

1. Foundation: desktop shell, CodeMirror, explorer, tabs, ordinary file I/O, settings, command registry.
2. Speed editing: snippets, nested placeholder sessions, cached math context, smart pairs, structural movements, contextual/chord bindings, core tests.
3. Intelligence: worker index, outline, command/label/citation completions, symbol navigation. Offline dictionary-backed prose spell checking uses a separate worker and personal dictionary stores.
4. Build: asynchronous configurable compiler, output and diagnostics, PDF preview. The embedded PDF.js reader retains page-relative position and zoom, renders replacements before swapping, and bounds live canvases to viewport-adjacent pages. SyncTeX supports forward/inverse navigation; PDF text/link layers remain follow-ups.
5. Customization: visual snippet and binding editors, portable JSON configuration, themes/profiles, recovery. Appearance exposes independently validated color roles; broader performance benchmarking remains follow-up work.
6. Advanced: CodeMirror multiple selections, declarative macros and provider boundaries. Matrix-specific navigation, plugin loading, and multi-file replace need further implementation.

Each release must pass core logic tests and a production TypeScript build. Native host integration tests cover conflict protection and asynchronous builds. Browser smoke checks cover typing, snippet tab stops, dialogs, and navigation. Performance claims beyond the bounded algorithms require measured large-project benchmarks.

## Live rendering (promoted in 0.2)

`LiveScheduler<T>` owns edit generations, pause/debounce, one in-flight operation, suppression of obsolete results, and a presentation-validity predicate. `LiveCompiler.build(root, request)` accepts a root file, engine/mode and source buffers; it mirrors a project into a reusable temporary directory and returns PDF bytes plus compile/sync timings. It never saves those buffers into the source project. Renderer-to-main access is limited to `liveBuild` and `cancelLive` IPC methods.

Live rendering passes a generation predicate into `PdfPreview.load` so obsolete results are checked during parsing, rasterization and before page swapping. Successful updates retain the reader's anchor. Invalid syntax preserves the last successful document. The application exposes manual full builds independently; choosing Build disables live mode first. The main app retains the quilltex package identity and port 5173; the preserved experiment keeps its isolated identity.

See `research/FEASIBILITY.md` for historical measured latency and remaining compatibility/performance questions.

## Appearance contract

`core/appearance.ts` defines the portable `Colors` model, color roles, presets, hex validation and accent foreground contrast. Flat color fields merge consistently with project overrides and older settings. The configuration validator supplies missing defaults and migrates legacy light profiles to dark. `services/appearance.ts` maps roles to CSS variables without rebuilding editor state. CodeMirror highlighting and the UI consume those same variables; color previews do not trigger compilation or edit transactions. Saving goes through the existing configuration persistence API. Closing an unsaved preview restores the active configuration.

## Practice contracts

- `core/practice.ts`: `Challenge {id, style, difficulty, topic, tex}` and `PracticeScore {id, style, difficulty, cpm, seconds, characters, date}`; delimiter normalization, score validation and partitioned top-ten records. No DOM dependencies.
- `core/practice-generator.ts`: DOM-free compositional grammar. `Expression {tex, shape}` nodes keep grouping explicit and record symbol-independent structure. Recursive scalar expressions split a finite node budget; domain productions add notation; a separate equation layer chooses relations, definitions, balances, chains or aligned systems. Short/standard/extended use budgets 2/6/12 and source caps 150/330/620. `generateChallenge(style, difficulty, rng?)` is stateless; `createChallengeGenerator(rng?)` returns a session-owned function with independent style/length histories. It excludes the most recent half of each style's topics and retries up to 24 candidates against 40 recent shapes and length limits, with a bounded short-form fallback for degenerate RNGs. This is syntactic practice, not symbolic algebra or physical-model generation. New notation belongs in domain productions; no renderer or editor changes are needed when it uses supported MathJax commands.
- `practice/workspace.ts`: owns a separate `WritingEditor`, target/input views, attempt generations, first-edit/last-edit timing, hint/paste eligibility, and local records. The command registry routes editing commands to the practice editor while it is open. Configuration changes reconfigure both editors. Main document state is preserved.
- `services/equation-renderer.ts`: explicitly enabled MathJax TeX packages produce a notation fingerprint and SVG with inline glyph paths. Fingerprints ignore math spaces and transparent single-child wrappers, while preserving tokens, node types and explicit font variants. They are a notation comparison, not symbolic algebra.
- `equation.worker.ts` serializes rendering away from the input thread and resolves dynamic font modules from locally emitted Vite chunks. No require/autoload/HTML package is enabled. Worker startup is lazy; the application does not load its renderer/fonts until practice opens. Source length, TeX macro limits and a five-second worker termination timeout bound malformed input.
- `EquationPreview.render(tex)` returns `{svg, fingerprint}`. The UI debounces changes by 65 ms and suppresses obsolete attempt/revision results. Closing terminates the worker, rejects pending requests, clears timers and destroys only the practice editor. Invalid edits retain the previous SVG with a stale-render status.

Validation includes 192 seeded generated equations across six style/length combinations, notation-equivalence checks, score validation, browser tests for settings reuse and persistence, and a built Electron test for local dynamic fonts and invalid-input retention. MathJax 4 modules are excluded from Vite development prebundling to keep font registration on one shared module instance.

## Clipboard editing

`core/editing.ts` defines pure term-selection growth, backward cut ranges, innermost brace-content ranges and overlap merging. The editor applies selection/cut/paste commands with isolated undo transactions and checks document/selection identity after asynchronous clipboard access. Read-only buffers reject mutations. Electron 44's asynchronous `clipboard.readText/writeText` is exposed through sender-checked IPC; the write promise is returned so cuts cannot delete before clipboard success. Browser mode uses `navigator.clipboard`. Both main and practice commands route through `commandEditor()`; practice recognizes custom clipboard paste as an assisted attempt.

## PDF pane and detached window

`PdfWorkspace` owns a persisted splitter ratio and docking lifecycle. Detach adopts the existing reader container into a same-origin blank window, so no second PDF parser, build subscription, or independent reader state is created. Styles are copied locally and color roles stay synchronized. Capture/restore uses the same page-relative position API across adoption and resize. Closing the popup reattaches the DOM; a small close watcher also recovers from closure paths that skip unload events.

Electron permits only the named `quill-pdf` blank popup, blocks its navigation and further popups, and preserves sandbox/context-isolation settings. The main IPC sender check continues to reject child-window host calls. Parent renderer throttling is disabled only while a detached reader exists so live painting continues if the main window is minimized. Child windows close with their parent.

Zoom records the PDF-space point under the pointer, relays out pages, then adjusts both scroll axes to keep that point stationary where scroll limits permit. Middle-click doubles zoom, Shift+middle-click halves it, middle-drag pans both scroll axes from their initial offsets without changing zoom, and Ctrl+wheel zooms incrementally. Explicit zoom is clamped to 25–800%; existing canvas pixel caps remain. Rasterization uses the current owner window's display pixel ratio.

`core/terms.ts` owns `TermRules {termSeparators, termWhitespace}` and pure `termRanges(text, rules?)`. The tokenizer keeps command names, escaped characters, double dollars and sized round/square delimiters atomic; literal separators match complete token sequences, longest first. Default rules exclude curly braces. Navigation, selection and backward cutting share the same live configuration in both WritingEditor instances. Missing settings migrate through configuration defaults; validation bounds rule count/length. GUI settings, project/global persistence and profile JSON all use these fields.

Term navigation requests `termRanges(text, rules, true)` to include each matched delimiter as a separate range. This makes forward/backward stops reversible across adjacent delimiters while keeping multi-token custom delimiters atomic. Selection and cutting use the default expression-only ranges.

## Spell checking contracts

- `core/spelling.ts`: `proseWords(text, comments)` returns UTF-16 `{from,to,word}` spans in a single forward scan; `dictionaryWords(unknown)` validates and normalizes personal word arrays. LaTeX metadata, math and verbatim regions are skipped; text-mode command arguments remain prose. No DOM or dictionary dependency.
- `services/spelling.worker.ts`: bundled nspell + English affix/dictionary data. Checks the active document and deduplicates word lookups after an idle debounce. Suggestions run only on request. No network, OS dictionary or document upload. At most 2,000 diagnostics are returned per pass.
- `editor/spelling.ts`: CodeMirror view plugin owns worker lifetime, debounce, revisions, decorations and pending suggestion requests. Edits invalidate old diagnostics; stale worker responses are discarded by revision and document identity. Disabled/destroyed editors terminate their worker. Configuration reconfigures the existing editor without touching history; asynchronous suggestions validate document identity before replacement.
- Settings: `spellCheck`, `spellComments`, `spellDisabledFiles`. Dictionary word arrays are separate host APIs (`loadDictionaries`, `saveDictionary`) and separate project/global JSON files, so saving a profile cannot promote project vocabulary into a global dictionary. File writes use the existing project path checks and atomic-write helper. Project dictionary JSON changes reload through the project watcher; global files reload through Reload configuration from disk.
- The practice editor uses the same extension and `@practice` as its file exclusion key. Each open editor has one lazy worker; checking happens off the UI thread after 450 ms idle. This is not incremental TeX expansion or semantic spell checking for arbitrary macro packages.

`ui-spelling-menu.ts` presents suggestions as a native nonmodal popover anchored to CodeMirror word coordinates and clamped to the viewport. In practice it belongs to the practice dialog so it remains interactive. It manages keyboard focus and removes listeners on outside dismissal, Escape, scrolling, resize, or parent close. Replacement still verifies document identity.

## SyncTeX contracts

- `desktop/synctex.cjs`: `SyncTexStore.capture(projectRoot, compilerCwd, pdfPath)` copies a PDF and its compressed/plain SyncTeX sidecar into an immutable temporary snapshot, indexes only project-contained source inputs and their SHA-256 hashes, and returns `{pdf,syncId}`. A missing/unusable map does not prevent PDF viewing. Source files newer than the PDF suppress synchronization. Live compilation enables `-synctex=1` and captures scratch-project inputs before returning bytes to the renderer.
- Native IPC accepts opaque snapshot IDs and validated positions, never arbitrary executables or shell commands. `synctex view/edit` run without a shell, with a five-second timeout, bounded output, and `SYNCTEX_EDITOR`/`SYNCTEX_VIEWER` removed. Inverse targets pass project path/symlink checks. Snapshot IDs are bound to the currently open project. One displayed snapshot is pinned; at most six recent snapshots are retained. App exit removes their temporary directory.
- `PdfPreview.load` accepts either legacy PDF bytes or `{pdf,syncId}`. The map identity commits together with the successfully rendered PDF, never with a failed or superseded load. `onPresented` pins it. `showSync` uses page viewport transforms, preserves zoom, and shows a short-lived point marker; Ctrl/Cmd-click transforms screen coordinates back into SyncTeX's top-left point coordinates. The adopted viewer DOM retains these handlers in detached windows.
- Forward requests include current source text, checked against the snapshot hash. Inverse responses include that hash; the renderer compares open buffers or disk content before opening and positioning the editor. Included source paths from live scratch directories map back to project-relative paths. This protects against line drift after edits; it does not interpret TeX macro expansion or guarantee character-level precision. Old external PDF/sidecar pairs without original source hashes can only be checked against source freshness when loaded.

## LaTeX delimiter highlighting

`core/delimiter-highlighting.ts` defines portable `HighlightSettings`, four presets, and `indexDelimiters(text) → {tokens,pairs}`. Tokens carry full source spans, family, nesting depth, pair ID and unmatched status. A stack plus keyed opener buckets prevents quadratic recovery on repeated unmatched closing tokens. Recovery marks abandoned inner openers and never creates crossing pairs. Sized directional delimiters pair by sizing commands, allowing asymmetric/invisible fences; escaped braces remain distinct from TeX groups. Comments/verbatim are skipped. `\middle` resolves to its enclosing left/right pair.

`services/delimiters.worker.ts` performs indexing off-thread. `editor/delimiter-highlighting.ts` owns worker lifecycle, an 80 ms edit debounce and revision checks. On edits it drops stale decorations; cursor/viewport changes only recompute visible marks from the cached index. A CodeMirror compartment applies settings in place, leaving text, history and movement behavior untouched. The generic CodeMirror bracket matcher is replaced by this presentation layer to avoid conflicting pair highlights. Its parser is intentionally independent of navigation semantics. Personal palettes validate as 1–12 six-digit colors; GUI, project/global config and profiles share `settings.delimiterHighlight`.
